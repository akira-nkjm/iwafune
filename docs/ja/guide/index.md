# iwafune ユーザーガイド

iwafune は小型衛星の概念設計のための作業環境です。設計は git で管理するプレーンな TOML ファイルのディレクトリとして持ちます。編集は `fune` コマンドラインツールか Web の GUI で行い、サブシステムの解析も同じデータに対して実行します。

このガイドは iwafune を初めて使う人向けです。ツールのインストール、設計の作成、解析の実行、判定の読み方を説明し、詳細が必要になったときの参照先を示します。

## 想定する読者

- 設計が固まる前に、質量・電力・データの各バジェットとサブシステムの簡易チェックが必要な、衛星システムのエンジニア
- 概念設計書を書き、書中の数値を 1 か所から取り出したい学生やプロジェクトチーム
- 設計レビューを、ブランチ、プルリクエスト、読みやすい差分によるコードレビューと同じ形で進めたい人

Rust や TypeScript の知識は要りません。必要なのは端末、git、そして衛星のサブシステムについての基本的な知識です。

## 3 つの原則

**設計データは git に置きます。** プロジェクトは `fune.toml` を含むディレクトリです。部品、モード、要求、軌道の設定、解析ケースは、小さな TOML ファイルになっています。値を 1 つ変えると、差分は 1 行です。どの値にも単位、出典、メモを付けられるので、レビューする人は数値の出どころを確かめられます。

**CLI と GUI は対等です。** どちらも同じコードを通して同じ編集をします。GUI で行った編集はすべて `fune` コマンドとして表示でき、その逆もできます。書き出されるファイルはバイト単位で同一です。作業に合うほうを使い、混ぜて使っても構いません。

**解析は判定を返します。** 解析は設計から入力を組み立て、主要な数値と判定（OK、警告、違反）を返します。設計に足りない入力があるときは、推測せずに止まります。不足している入力を、それぞれを埋める方法とともに一覧で示します。

## iwafune がしないこと

- 概念設計のためのツールです。解析は初期のトレードオフを見るための単純で型付きのモデルです。CAD、熱解析ソルバー、本格的な有限要素法のパッケージなど、詳細設計のツールの代わりにはなりません。
- 実在する部品のデータは同梱していません。デモのプロジェクトは架空のものです。値は自分のデータシートや試験から入力し、それぞれの出典を記録します。
- PDF の報告書は作りません。`fune report export` は表と図を書き出すので、自分の Typst 文書から取り込みます（[報告書の出力](../../report.md)を参照）。
- ミッション目的や成功基準を表すエンティティはありません。要求は平らな一覧で、木構造にはなっていません。[ロードマップ](../../roadmap.md)を参照してください。
- GUI は 1 つのプロジェクトのためのローカルな Web サーバーです。共同作業は共有の GUI サーバーではなく git で行います。

## このガイドの表記

- 出力のブロックでは `$` で始まる行が入力するコマンドです。`$` のない行はプログラムの出力です。
- `…` だけの行は長い出力を省略したことを示します。ホームやプロジェクトのパスは `~/…` や `/path/to/…` に短くしています。
- `my-sat/` と `my-demo/` は例のディレクトリです。名前は自由に付けてください。
- スクリーンショットの位置はソースでは HTML コメントで示しています。ドキュメントのサイトではこれが画像に置き換わります。
