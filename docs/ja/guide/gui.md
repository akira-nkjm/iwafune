# GUI ガイド

GUI は`fune` がプロジェクトのディレクトリから配信する Web アプリケーションです。CLI と同じファイルを読み書きするので、どちらで編集しても、結果は両方で見られます。このページでは左のナビゲーションの順に、ページごとに説明します。各ページについて、何が表示されるか、何を編集できるか、典型的な作業を示します。多くのページで繰り返すパターンはページの前の節でまとめて説明します。

プロジェクトの中から起動します。

```bash
fune gui            # http://127.0.0.1:3000, or the next free port; opens the browser
fune gui --no-open  # do not open the browser
```

GUI には英語と日本語の辞書があります。このガイドは日本語の GUI のラベルを使い、サイドバーの項目には英語のラベルを括弧に添えます。

## ウィンドウ

<!-- screenshot: / — ウィンドウ全体: 左にセクションを並べたサイドバー、右に Overview ページ -->
*ウィンドウ: サイドバーとページ。*

サイドバーにはプロジェクト名、検索ボックス、ナビゲーションがあり、下部にはプロジェクトの git のブランチとリビジョン、診断のカウンター、「変更履歴」の行、言語の行、外観の行があります。ナビゲーションには 5 つのセクションがあります。

| セクション | ページ |
|---|---|
| （最上部） | 概要（Overview） |
| 設計（Design） | コンポーネント（Components）、カタログ（Catalog）、配置（Layout）、システム図（System diagram）、モード（Modes）、要求（Requirements） |
| 系の解析（Subsystems） | サブシステムごとに 1 ページ |
| 前提条件（Conditions） | 軌道と地上局（Orbit & stations）、解析ケース（Analysis cases）、フェーズ（Phases） |
| プロジェクト（Project） | 診断（Diagnostics）、設定（Settings）、単位と定義（Units & definitions）、出典（Sources） |

`fune gui` を実行すると、「概要」ページが表示され、タイトルの下に部品、モード、ネット、ケースの数が出るはずです。

- 検索: 検索ボックスをクリックするか、`Ctrl+K`（Mac では `⌘K`）を押します。数文字を入力して、ページ、部品、ネット、モードを選ぶと、そこへ移動します。
- サイドバー: `Ctrl+B`（`⌘B`）で、サイドバーを開閉します。閉じると、アイコンの細いレールが残ります。
- 診断のカウンター（ブランチ名の下のエラーと警告）: `fune check` と同じ件数です。クリックすると、「診断」ページが開きます。
- 変更履歴: この行は、このセッション（ページを読み込んでから）に行った変更を、新しい順に並べたポップオーバーを開きます。各項目には同じ編集をするコマンドと、それをコピーするボタンがあります。取り消しとやり直しの操作も並びます。ポップオーバーの見出しには **元に戻す** と **やり直す** のボタンがあり、`Ctrl+Z`、`Ctrl+Y` と同じ操作をします（[取り消しとやり直し](#取り消しとやり直し)）。
- 言語: 「言語」の行で、日本語と英語を切り替えます。選択はブラウザーに記憶されます。
- 外観: 「外観」の行で、「OS に従う」、「ライト」、「ダーク」を選びます。

GUI がサーバーに接続できないと、カウンターの下に赤い「サーバーに接続できません」の枠が出ます。`fune gui` がまだ動いているかを確かめてください。

## 多くのページで使うパターン

### 編集ダイアログと「同じ操作のコマンド」のプレビュー

複数の値が必要な編集では、ダイアログが開きます。部品の追加、モードの追加、要求の追加、名前の変更などです。ダイアログはウィンドウの上寄りに置かれます。ウィンドウより高いときはダイアログの中でスクロールし、ボタンには届いたままです。`Enter` で確定します。確定のボタンと同じく、ダイアログにエラーがない間だけ有効です。入力が有効になるまで、確定のボタンは無効のままです。

確定する前に、ダイアログには **同じ操作のコマンド** という箱が出ます。次の内容が入っています。

- 同じ編集をする `fune` コマンド（複数のこともあります）と、**コマンドをコピー** ボタン。
- 「変わるファイル:」の行。開くと、ファイルごとの差分を読めます。ラベルは「新規」、「変更」、「削除」、「名前変更」です。
- 警告と、編集が拒否される場合はその理由。

プレビューはドライランから作られるので、確定のボタンを押すまで、何も書き込まれません。CLI を学ぶときや、コマンドをスクリプトにコピーするときに使ってください。既存のレコードのフィールドが抜け落ちる編集のとき（たとえばケースを置き換えるとき）は、プレビューに「<file> から消えます: <keys>（新しい内容に含まれていません）」と出ます。

小さな編集ではダイアログを使いません。ホバーしたときに鉛筆が出る値は、クリックして入力し、`Enter` で保存、`Escape` で取りやめます。値は単位つきのテキストで入力します（たとえば `1.2 kg`）。サービスは`fune set` とまったく同じ読み方をします（[値の書式](cli.md#値の書式)）。エラーは欄の下に表示され、何も書き込まれません。

編集が保存されると、変わったファイルを示す短いメッセージが出ます。その間に設計がほかで変わっていると（ファイルの編集や CLI の実行）、メッセージに「ほかの場所で設計が変わりました」と出ます。GUI は最新の設計を読み込み直すので、もう一度操作してください。

### 使われているものの削除

ケース、フェーズ、モード、形態、回線、地上局、カタログの項目は、そのページから削除できます。まだ何かが参照していると、削除は拒否されます。ダイアログのプレビューが、何が参照しているかを挙げたメッセージで、理由を示します。たとえば「Analysis case hot_imaging cannot be removed: referred to by `default_case` in analysis/common.toml; `quantify.cases` of requirement(s) R_STORAGE. Change those first」のようになります。先にそれらを変えてから、削除してください。CLI も同じメッセージを出します（[ケース](cli.md#ケースフェーズ形態)）。削除が通った場合は、取り消せます。

### 不足している入力の行と対処の操作

解析の入力が不足していると、サブシステムのページの **足りない入力（n）** の下に、その一覧が出ます。各行は不足している項目と理由を示します。埋め方が分かる行には、リンクのような操作があります。

| 操作 | 開くもの |
|---|---|
| 「値を入れる」 | 値を入力するダイアログ。部品がカタログの項目を使っているときは、書き込み先を選びます。「この部品の上書き」か、カタログの項目（それを使うすべての部品に適用）です |
| 「部品に値を入れる」 | 部品を選んで値を入力します。その部品の上書きとして保存されます |
| 「既存の部品を割り当てる」 | ある役割を担う部品を選びます。その部品の種類が、その役割を持つ種類に変わります |
| 「部品を追加」 | 不足している種類に合わせて設定済みの、「コンポーネント追加」ダイアログ |
| 「部品を選ぶ」、「カタログ品を選ぶ」、「回線を選ぶ」、「形態を選ぶ」、「マヌーバを選ぶ」 | 設計の中にある選択肢の一覧 |
| 「モードを追加」、「マヌーバを追加」、「地上局を追加」、「通信の回線を追加」、「解析ケースを追加」 | そのページの追加ボタンと同じダイアログ |

これらは`fune analyze` がコマンドとして表示するものと同じ対処です（[チュートリアルのステップ 11](first-satellite.md#11-解析を実行して不足している入力を埋める)）。どのダイアログにも、コマンドのプレビューが出ます。不足している入力は「概要」ページのバジェットと、「要求」ページ（「入力が足りません」）にも出ます。

### ケースの選択

どのサブシステムのページにも、右上に「解析ケース」というラベルの選択欄があります。最初の項目は「自動（必要な解析だけ既定）」です。ケースが必要な解析は既定のケースを使い、ほかの解析はすべてのモードを見ます。既定のケースが決め手になるときは、「条件選択が必要な解析の既定: <ケース>」と表示されます。ケースを選ぶと、そのページのすべての解析を、そのケースで実行します。横の **再計算** ボタンは、解析をもう一度実行します。

選択はページのアドレス（`?case=<ID>`）に保存されるので、リンクを共有できます。リンクが指すケースがもうなければ（削除した、名前を変えた、作成を取り消した）、ページは既定の選択を表示し、「解析ケース <ID> はもうありません。既定の選択で表示しています。」という通知を出します。

### 形態の選択

「配置」ページには「配置の形態」という選択欄があり、最初の項目は「基準」です。どの形態の部品の姿勢を見て編集するかを選びます（[概念](concepts.md#形態)）。形態を選んで部品を動かすと、姿勢はその形態だけに書かれます。「形態を管理」で、形態を追加、編集、名前変更、削除します。選択はアドレス（`?configuration=<ID>`）に保存されます。

### 取り消しとやり直し

`Ctrl+Z`（`⌘Z`）は直前の編集を取り消し、`Ctrl+Y`（`⇧⌘Z`）はやり直します。どちらもウィンドウのどこでも使えますが、文字を入力する欄の中では入力の取り消しになります。サイドバーの「変更履歴」ポップオーバーの見出しにある **元に戻す** と **やり直す** のボタンや、「システム図」ページのツールバーのボタンも使えます。

履歴は `fune undo` と `fune redo` が使うものと同じです。そのため、CLI の編集を GUI から取り消すことも、その逆もできます。ポップオーバーの一覧はこのブラウザーのタブで行ったことを表示します。ページを読み込み直すと空になりますが、取り消しの履歴そのものはプロジェクト（`.fune/history.json`）に残っています。編集のあとにファイルがほかの方法で変わっていると、取り消しは拒否されます。

### 表とツリー

表の見出しは並べ替えができます。1 回クリックすると昇順、もう一度で降順、3 回目で元の順序です。ツリーには「すべて開く」と「すべて閉じる」があります。検索ボックスは見えるものを絞り込みますが、設計は変えません。

### 3D ビュー

「配置」ページと、「熱」ページの「熱画像」タブは、衛星を 3D で表示します。

| 操作 | 方法 |
|---|---|
| 回転（軌道を回る） | 左ボタンのドラッグか、指 1 本のドラッグ。どの軸まわりにも回せ、上下を逆にもできます |
| 平行移動 | マウス: 中ボタンか右ボタンのドラッグ、または Shift を押しながら左ドラッグ。トラックパッド: 2 本指のスクロール |
| ズーム | マウスのホイール、またはトラックパッドのピンチ。ポインターを中心にズームします。右上の縮小と拡大のボタンは、中心を基準にズームします |
| ある方向から見る | 右下の**ビューキューブ**の面、辺、角をクリックします。傾きのない、いちばん近い正立の視点へ動きます。角を選ぶと、立方体の対角線に沿った Y 字形の眺めになります |
| ビューを回す | ビューキューブの横にある 2 つの曲がった矢印（反時計回りと時計回り）が、見ている方向を軸に画面を回します。角から見ているときは 120°、それ以外は 90° です |
| リセット | 右上の **ホームポジション**（家の形）ボタンで、カメラと向きを初期状態に戻します |
| ヘルプ | 右上の疑問符のボタンが、これらの操作を一覧にします |

### 2D の図のビュー

「システム図」ページは同じ考え方を 2D で使います。ホイールかピンチでズームし、2 本指のスクロールか、背景または中ボタンのドラッグで平行移動します。`+`、`-`、`0`（全体を表示）、`1`（100 %）、`F`（選択した項目へズーム）のキーは、文字入力の欄にフォーカスがないときに使えます。

## 概要

表示するもの: 「概要」ページはプロジェクトのダッシュボードです。サブタイトルに、名前と、部品、モード、ネット、ケースの数が出ます。

- KPI カード: 解析から得た代表的な数値で、たとえば「質量余裕」です。各カードには値、充足率のバー、判定の色、関連する数値の行があります。カードをクリックすると、その元になっているサブシステムのページが開きます。設計にとって表示するものがないカードは、表示されません。
- 前提条件: 軌道と環境のカードの 2 行目です。
- バジェットのパネル: バジェットの種類（質量、電力、データ量）ごとに 1 つです。パネルにはバジェットの題、モードまたはケース、余裕、限度とシステム余裕、サブシステムごとの行（現在値、成長余裕込みの値、配分、余裕）、合計があります。質量バジェットでは設計に推進系があると、「乾燥」と「推薬込み」の合計と推薬の行が出ます。「上限は要求 R_… から（編集は要求で）」は、限度の置き場所を示します。値のない部品の行は集計していないものとして挙げられます。バジェットの不足している入力も挙げられます。
- 診断: エラー、警告、情報の件数と「すべて見る」。

編集できるもの: このページでは何も編集しません。カードと行は編集できるページへのリンクです。

典型的な作業: 編集のあと、ここに戻って、バジェットが赤くなっていないかを確かめます。

## 設計

### コンポーネント

表示するもの: 「コンポーネント」は部品を一覧にします。タブは 3 つです。

- 一覧: サブシステム、グループ、組立品ごとにまとめたカード。
- ツリー: `parts/` のディレクトリ構造を持つ、プロダクトツリー。
- 表: 部品ごとに 1 行。ID、系、種別、カタログ、員数、質量、電力（状態ごと）、未入力、診断を並べます。並べ替えができます。

「部品を検索」（ID、種別、カタログで探します）と系のフィルターで、一覧を絞り込めます。部品を選ぶと詳細が開き、サブシステムをまたいで、その部品のすべてが表示されます。

| セクション | 表示するものと、編集できるもの |
|---|---|
| 基本 | 種別、カタログ、「トレード候補」の中で選んだ候補、員数、冗長、成熟度、系、置き場所 |
| 属性の表 | サブシステムごとに 1 つの表（質量、姿勢系、電源、熱 など）。各値と出どころ（カタログ、上書き、出典）、上書きを消してカタログの値に戻すリセットボタンを表示します。値をクリックすると編集できます。**パラメーター追加** は、出典、出典内の場所、注記つきで属性を追加します |
| 配置 | 「取付先」、「取付先の部品」、「取付点」、「取付点からの位置」、姿勢（X、Y、Z 軸まわりの角度）、導出した機体座標の姿勢、形態ごとの姿勢の上書き |
| 接続 | ポートと、それぞれが接続するネット |
| モードでの状態 | 各モードでの部品の状態と、モード表へのリンク |
| ハーネス | 部品に接続するケーブルのセグメント |

編集できるもの: 値（クリックして編集）、配置、部品そのものです。**追加** は「コンポーネント追加」ダイアログを開きます。系か組立品を選び、「カタログから」（カタログを検索して項目を選ぶ）か「種別だけ」を選んで、ID を付けます。部品のメニューには「名前を変える」、「グループにまとめる…」、「削除」があります。名前を変えると、参照がすべて一度に書き換わります。

典型的な作業: カタログから部品を追加し、質量の上書きを設定します。「追加」を押し、項目を選び、ID を付けて確定します。次に部品を開き、質量の値をクリックします。

### カタログ

表示するもの: 「カタログ」はすべてのカタログの項目を一覧にします。自分のカタログ（`local/…`）と共有カタログです。タブは「ツリー」と「表」です。フィルターはカタログ、種別、検索ボックスです。「分け方」はツリーを「カタログ別」、「メーカー別」、「種別別」、「成熟度別」、「タグ別」、「系別」で分けます。項目を選ぶと、「基本」（名前、英語名、メーカー、型番、成熟度、タグ、データシート）、「値」、「ポート」、「状態」と、一覧「使っている部品（n）」（その項目を使っている部品）が表示されます。

編集できるもの: 値と、項目の名前の変更と削除です（部品が使っている間は、削除が拒否されます）。「部品として設計に追加」は、項目から部品を作ります。**カタログ品を作る** は、項目を作ります。既存の部品の値をコピーすることもできます。共有カタログの項目は読み取り専用です。「共有カタログ（<名前>/…）の品は読み取り専用です。値を直すときは共有リポジトリに PR を出すか、部品の側で上書きします。」と表示されます。**共有カタログ** ボタンは、共有カタログの一覧と状態を表示するダイアログを開きます。

- **取得** は`catalog.lock` に記録されたコミットをダウンロードします。`fune catalog fetch` と同じです。
- **更新** は記録を最新のコミットへ進め、追加、削除、変更された項目を表示します。
- **共有カタログを足す** は、名前、git の URL、rev を尋ねます。`fune.toml` にエントリを追加します。そのあと「取得」を押してください。

取得や更新のあとは、`catalog.lock` をコミットしてください。カタログのダイアログは一度に 1 つだけ表示されます。

典型的な作業: 新しいコンポーネントを一度だけ記述します。「カタログ品を作る」を押し、出典つきで値を入力してから、「部品として設計に追加」を使います。

### 配置

表示するもの: 「配置」は配置の 3D エディターです。見出しに、配置済みの部品の数と、未配置の部品の数が出ます。白黒の球は重心の印です。

- 部品のツリー（左）: プロダクトツリーです。目のボタンで部品を表示・非表示にでき、「<part> だけ表示」で 1 つだけを取り出せます。
- シーン: 箱をクリックして選びます。「操作」はシーンの中の「移動」か「回転」のハンドルを選びます。「スナップ」は動きを丸め、「構造の不透明度」は構造を透明にして、中を見られるようにします。
- 座標の表示: 「視野」（視野の円錐）、「原点の軸」、「格子」、「ビューキューブ」、「太陽」、「枠線だけ」の切り替えです。
- 軸・法線・視線: 色つきの線で、スピン軸、磁気トルカの軸、法線、視線（ボアサイト）、推力の方向を示します。
- 所見: 「解析の所見を色で示す」は、構造の解析が見つけた重なりと、プルームや視野の干渉に色を付けます。一覧「所見の一覧」はそれを挙げ、部品を選べます。大きさのない部品はひし形のマーカーで描かれます。
- 配置の形態（上部）: 上の形態の選択を参照してください。ビューの操作は[3D ビュー](#3d-ビュー)にあります。

編集できるもの: 「<ID> の配置」のパネルで、取付先、位置、向きを数値で変えられます。移動や回転のハンドルで、部品をドラッグすることもできます。形態を選んでいるときは、変更はその形態に入ります。

典型的な作業: 新しい部品を配置します。「コンポーネント」で追加し、「配置」で箱を選んで、「取付先」、取付点、位置を設定します。

### システム図

表示するもの: 「システム図」は部品をカード、ネットを線として描きます。電源と信号の接続で、電源系はレールごとに色分けされます（バッテリー、太陽電池アレイ、非安定化バス、安定化レール）。部品のグループはコンテナとして描かれます。

- ツールバー: 「表示する系」は、サブシステムを隠します（構造は既定で隠れています）。「層」は「給電」、「信号」、「GND」の表示を切り替えます。「同種をまとめる」は、同じカタログの項目と接続を持つ兄弟の部品を、1 枚のカード「×N」として表示します。
- 「詳細」パネル: カードか線を選ぶと、詳細が出ます。ネットには「レール電圧」、「電流制限」、「プロトコル」、ポートの一覧と、「切り離す」、「削除」があります。
- ズームのボタンとキー、全体のマップ、**元に戻す** と **やり直す** のボタン。

編集できるもの: 位置、経路、接続です。カードやグループをドラッグすると動きます。ポートから別のポートへドラッグすると、接続します。どちらもネットにないときは、ダイアログがネットを作ります。線の端をドラッグすると、カードの縁の別の場所へつなぎ直せます。線の区間をドラッグすると、手で経路を決められます。区間をダブルクリックすると曲がり角が増え、曲がり角をダブルクリックすると消えます。「位置を自動に戻す」は、動かしたカードを自動配置に戻し、手で描いた配線は残します。「位置と線を自動に戻す」は、両方を消します。

典型的な作業: 新しい部品を電源のレールにつなぎます。部品の電源ポートから、レールのポートへドラッグします。

*システム図。*

### モード

表示するもの: 「モード」はモード表です。列がモード、行が部品です。マトリクスのタイトル行は「部品 × モード」です。「表示する期間」で「日照」と「蝕」を切り替えると、蝕のときの状態の上書きが見えます。マトリクスの下には1 台あたりの消費電力、成長余裕込みの合計電力、「使用可能電力」、「余裕（システム余裕確保後）」が出ます。パネルはエネルギーバランスが繰り返す、名前つきのモードシーケンスを一覧にします。「解析に使う」で 1 つ選びます。

次の操作で編集できます。

- 状態の切り替え: セルをクリックすると、部品のオンとオフを切り替えます。右クリックするか `D` を押すと、別の状態と「割合」（各軌道周回のうち、別の状態で過ごす時間の割合。0 から 1）を選べます。凡例は「● オン」、「◐ 間欠」、「— オフ」です。
- モードの列: 「モード追加」は、モードを作ります（別のモードをコピーできます）。列のメニューで、名前の変更、削除、左右への移動ができます。モードには「最長継続時間」と、その評価のタイミング（「使う時間帯」と「開始の基準」）を設定できます。
- 保存: セルの変更は下書きとして集められます。下のバーに「モード表を保存（n セル）」と出て、ダイアログと同じコマンドのプレビューを示します。合計と余裕には下書きがすでに反映されています（「まだ保存していません」）。保存を押すと書き込み、破棄もできます。

典型的な作業: ダウンリンク中はカメラをスタンバイにします。DOWNLINK の列でそのセルを右クリックし、状態を選んで、保存します。

### 要求

表示するもの: 「要求」には 2 つのタブがあります。

- 適合表: 要求ごとに 1 行です。要求の文、制約、ケース、「確かめる先」（解析かバジェット）、結果、判定を並べます。上部には件数として、「要求」、「満たす」、「注意」、「違反」、「未確認」が出ます。未確認の行は理由を示します。「確かめる先が書かれていません」、「入力が足りません」、「解析が失敗しました」などです。
- 要求の一覧: 要求を並べた一覧です。「要求を追加」、「編集」、「削除」があります。

編集できるもの: 要求です。ダイアログでは「短い名前」、「要求の文」（と「英語の文」）、「制約する量の次元」、「出典」、「制約の向き」と「値」、「成り立つケース」、そして「確かめる解析」と「解析の判定のキー」、または「確かめるバジェット」を指定します。入力した量は`fune requirement add` とまったく同じ読み方をします。

典型的な作業: 質量の限度を追加します。「要求を追加」を押し、量は Mass、向きは「以下」、値を入れ、確かめるバジェットは「質量」にします。「概要」ページの質量バジェットに、その限度が表示されます。

## 系の解析

表示するもの: サブシステムごとに 1 ページあります。電源、通信、熱、姿勢系、C&DH、推進、構造、ミッション機器です（ミッション機器にはまだ解析がありません）。名前は、プロジェクトの語彙に従います。サブシステムのページには右上にケースの選択と **再計算** ボタンがあり、その下にタブが並びます。タブはサブシステムによって異なります。

| タブ | 対象 | 表示するもの |
|---|---|---|
| 概要 | すべて | 「解析」の表。解析ごとに 1 行で、種類、主な結果、判定、不足している入力の数を示します。行をクリックすると、その解析のすべての KPI、グラフ、判定の文、不足している入力が開きます。「熱」ページの「概要」は、代わりに、節点の温度と範囲のグラフを表示します（保管、動作、性能の各帯域、定常状態の点、過渡の棒） |
| マヌーバ | 推進 | 実行順のマヌーバ。「マヌーバを追加」、「編集」、「削除」があります。下を参照してください |
| 熱画像 | 熱 | 部品を、その節点の温度で色分けした 3D 表示です。「温度の出どころ」（全ケースの最高、定常ケース、非定常で時刻を選ぶ）、「再生」、「色の範囲」を選べます。軌道の図は、太陽の側を示します |
| 結合と表面 | 熱 | 節点間の伝導と放射の結合、外面のコーティング、コーティングの表。値を入力すると、上書きが書かれます。節点の温度への影響は、保存の前に表示されます |
| 解析結果 | 熱 | 解析ごとに 1 枚のカードで、判定、値、表を表示します（ほかのサブシステムでは、これらを「概要」に表示します） |
| モード | 電源、C&DH、熱、姿勢系 | サブシステムのモードごとの値を、日照と蝕に分けて表示します（GUI のモードビュー。`fune mode view <system>`）。「電源」は、「日照中の電力の行き先」と、バッテリーから出す蝕の電力も表示します。姿勢系は、各モードの姿勢則と機器を表示します |
| 時系列 | すべて | 時系列解析のグラフ。そのような解析を実行すると表示されます |
| 設定 | すべて | サブシステムの設定と、それがあるファイル。値はその場で編集できます。表の下には、解析ごとに折りたたみのブロックがあり、その解析に渡した入力を表示します |

各解析は[解析のページ](../analyses/index.md)で説明しています。

編集できるもの: 設定をその場で編集でき、不足している入力の対処もできます（上を参照）。2 つのページにはさらに操作があります。

- 「通信」ページには「回線を足す」ボタンと、一覧「通信の回線」があります。回線を追加するときは、方向、送受信機の部品、地上局が性能を持っている帯域を指定します。一覧の各回線には編集と削除のボタンがあります。編集では回線の名前を変えることもでき、その場合は、その回線を指すダウンリンクの選択と要求のチェックも書き換わります。要求のチェックがその回線を指している間は、削除が拒否されます。損失と変調方式は「設定」タブで書きます。
- 「構造」ページには「幾何の所見」が並びます。箱どうしの重なりと、円錐の中にある部品です。所見には理由をつけて「承知する」操作ができます。承知した所見は警告ではなくなりますが、一覧に残ります。「承知を取り消す」で、承知を取り下げられます。

典型的な作業: 「電源」ページで、エネルギーバランスの不足している入力を、行の操作で埋めて、行に判定が出るまで進めます。[チュートリアル](first-satellite.md#11-解析を実行して不足している入力を埋める)では、同じことを CLI で行っています。

*サブシステムのページ。*

### マヌーバ

「マヌーバ」タブは各マヌーバを、区分、方式、スラスタ、目標つきで一覧にします。**マヌーバを追加** は、`fune maneuver add` と同じフィールドを持つダイアログを開きます。マヌーバには順序があります。1 つを削除すると、次のマヌーバが、その前のマヌーバにつなぎ直されます。

## 前提条件

### 軌道と地上局

表示するもの: `conditions/` の設定（軌道、地上局、期間）を表にしたものと、それに依存する解析です。

- β と蝕の季節変動: 1 年にわたるグラフです。
- 高度の推移: 抗力による軌道の減衰です。太陽活動のプリセットと、宇宙天気の表を取得してあれば、日付つきの値を使えます。表がないときは、「設定」で取得するようにページが案内します。
- 地上局ごとの可視。

次の操作で編集できます。

- 「このケースを作る」は、蝕が最長の日付か、β が最小の日付を、解析ケースにします（ケースの ID と、任意でモードを尋ねます）。
- **地上局を足す** は、ID、単位つきの緯度と経度、任意で高度と最小仰角を尋ねます。-90 から 90 deg の外の緯度や、0 から 90 deg の外の最小仰角は拒否されます。地上局は名前の変更も削除もできます。通信の解析が一覧に挙げている間は、削除が拒否されます。帯域ごとの性能は設定に書きます。
- 軌道の値は設定の表でその場で編集します。

典型的な作業: 回線設計で使う地上局を追加し、可視を確かめます。

### 解析ケース

表示するもの: 「解析ケース」は`cases/` のケースを、名前、説明、モード、フェーズ、開始時刻、ファイルつきで一覧にします。各行にある 2 つのアイコンのボタンが、ケースの名前の変更と削除をします（ツールチップは「ケース <ID> の名前を変える」と「ケース <ID> を消す」）。メニューのボタン「このケースで開く」は、サブシステムのページの一覧を表示します。1 つ選ぶと、そのケースを設定した状態でページが開きます。

次の操作で編集できます。

- 「ケースを足す」: ID、「表示名」、「説明」、「モード」、「フェーズ」、「不確かさの側」、「熱の環境条件」、「β 角」（単位つき。たとえば `60 deg`）、「周回数」、「太陽からの距離」、「開始時刻」を指定します。すでにある ID でケースを追加すると、置き換わります。プレビューは削除されるフィールドを挙げます。
- 「フェーズを選ぶ」と「開始時刻を入力する」は、ケースのフィールドを 1 つ編集します。
- 「最悪の日からケースを作る」は、フェーズの軌道のミッションの幾何から、3 つのケースを作ります。
- 名前の変更は、既定のケースと、要求に書かれたケースを書き換えます。削除は何かがそのケースを参照している間は拒否され、メッセージが何が参照しているかを示します。

典型的な作業: 最悪の蝕のケースを追加し、「このケースで開く」で、そのケースの「電源」ページを見ます。

### フェーズ

表示するもの: 「フェーズ」は`phases/` を順に一覧にします。名前、並び順、「始まりの条件」、「終わりの条件」、期間、使うモード、上書き、そのフェーズを指す解析ケースを示します。

編集できるもの: **フェーズを追加**、**編集**、**削除** はほかのページと同じように使えます。ケースがフェーズを指している間は、削除が拒否されます。**上書きを編集** は、軌道の上書き（設計の軌道をコピーして、値を 1 つずつ編集）と、モードごとの姿勢則の上書きのためのダイアログを開きます。上書きはそのフェーズを指すケースにだけ適用されます。

典型的な作業: 廃棄フェーズの軌道を低くします。「上書きを編集」を押し、設計の軌道をコピーして、高度を変え、ケースでそのフェーズを指定します。

## プロジェクト

### 診断

表示するもの: 設計のすべての診断を、重さ、コード、メッセージ、ファイルつきで表示します。「重さで絞る」のフィルターもあります。`fune check` と同じ結果です。

編集できるもの: ここでは何も編集しません。エラーはそれが指すもののページか、ファイルで直します。

典型的な作業: サイドバーのカウンターが赤くなったら開き、エラーから順に片付けます。

### 設定

表示するもの: 「設定」には 3 つの部分があります。

- プロジェクト: 「名前」、「場所」、「ブランチ」、「リビジョン」、「スキーマの版」。
- 外部データ: 任意のデータセット（DE440 の天体暦、宇宙天気の表、放射線データ）です。各行に、データセットの ID、状態（「読み込み済み」、「キャッシュ済み」、「未取得」）、サイズ、取得した日時、それを使うもの、ライセンスまたは出典の表示が出ます。
- 設定の表: 「前提条件」、「解析」、「バジェット」に分けた表で、列は「キー」、「値」、「ファイル」です。

編集できるもの: 設定の表の値はその場で編集します。「未設定」のキーには入力した値を指定できます。データセットの **取得** ボタンは、`fune data fetch <ID>` と同じく、そのデータセットをダウンロードします（[インストール](install.md#任意のデータセット)）。`gh` や `curl` がないなどのエラーは、行の下に表示されます。

典型的な作業: 日付つきの値で軌道寿命の解析を実行する前に、宇宙天気の表を取得します。

<!-- screenshot: /project/settings — Project パネル、Fetch ボタンのある External data パネル、設定の表 -->
*「設定」ページ。*

### 単位と定義

表示するもの: 3 つのタブがあります。**単位** はすべての単位を次元と SI 係数つきで表示し、「単位の試し打ち」は、入力した単位を解釈して、次元と SI の値を表示します。**属性定義** は組み込みと自分の属性定義、**種別定義** は、種別の定義です。

編集できるもの: 「属性を追加」と「種別を追加」で自分の定義を作れ、名前も変えられます。組み込みの定義は名前の変更も削除もできません。

典型的な作業: 入力したい単位、たとえば `mN*m*s` が使えるか、その次元は何かを確かめます。

### 出典

表示するもの: 登録簿 `sources/` です。ID、種類、名前、参照先、版、取得日、SHA-256、配布の区分、日付、記入者を示します。「開く」は参照を開きます。

編集できるもの: **出典を追加** と **編集** は、出典を書きます。共有カタログの出典は読み取り専用です（「共有」）。出典を削除するには `fune source rm` を使います。値がその出典を引いている間は、拒否されます。

典型的な作業: データシートの値を入力する前に、データシートを登録します。そうすると、各値がそれを引用できます。

## 典型的な作業と実行する場所

| 作業 | 場所 | 対応する CLI |
|---|---|---|
| 設計が健全かを見る | 概要、診断 | `fune status`、`fune check` |
| カタログから部品を追加する | コンポーネント、追加 | `fune part add <ID> --catalog <ITEM>` |
| 値を変える | コンポーネント、部品、値をクリック | `fune set <PART>.<ATTR> "<value>"` |
| 部品をモードに入れる | モード、セルをクリック | `fune mode set <MODE> <PART> <STATE>` |
| 部品を配置する | 配置、またはコンポーネントの配置 | `fune part place <ID> --on <PART> …` |
| 2 つのポートをつなぐ | システム図、ドラッグ | `fune net connect <PART>.<PORT> <NET>` |
| バジェットを読む | 概要 | `fune budget mass\|power\|data` |
| ケースを指定して解析を実行する | サブシステムのページ、ケースの選択 | `fune analyze <ID> --case <CASE>` |
| 不足している入力を埋める | サブシステムのページ、行の操作 | `fune set …`（ダイアログに表示） |
| 要求を追加する | 要求 | `fune requirement add …` |
| 通信リンクを追加・編集する | 通信、通信の回線 | `fune link add …`、`fune set analysis.comm.link.<name>.<field> …` |
| 間違いを取り消す | `Ctrl+Z`、または変更履歴 | `fune undo` |
| 外部データを取得する | 設定、外部データ | `fune data fetch <ID>` |
| 共有カタログを追加する | カタログ、共有カタログ | `fune catalog source add …` と `fune catalog fetch` |

GUI はすぐにファイルへ保存し、隠れた状態を持ちません。変更を残すには、git でコミットします。
