# GUI ガイド

GUI は`fune` がプロジェクトのディレクトリから配信する Web アプリケーションです。CLI と同じファイルを読み書きするので、どちらで編集しても、結果は両方で見られます。このページでは左のナビゲーションの順に、ページごとに説明します。各ページについて、何が表示されるか、何を編集できるか、典型的な作業を示します。多くのページで繰り返すパターンはページの前の節でまとめて説明します。

プロジェクトの中から起動します。

```bash
fune gui            # http://127.0.0.1:3000, or the next free port; opens the browser
fune gui --no-open  # do not open the browser
```

GUI には英語と日本語の辞書があります。このガイドでは英語のラベルを使い、日本語のラベルを括弧に添えます。

## ウィンドウ

<!-- screenshot: / — ウィンドウ全体: 左にセクションを並べたサイドバー、右に Overview ページ -->
*ウィンドウ: サイドバーとページ。*

サイドバーにはプロジェクト名、検索ボックス、ナビゲーションがあり、下部にはプロジェクトの git のブランチとリビジョン、診断のカウンター、「Change history」（変更履歴）の行、言語の行、外観の行があります。ナビゲーションには 5 つのセクションがあります。

| セクション | ページ |
|---|---|
| （最上部） | Overview（概要） |
| Design（設計） | Components（コンポーネント）、Catalog（カタログ）、Layout（配置）、System diagram（システム図）、Modes（モード）、Requirements（要求） |
| Subsystems（系の解析） | サブシステムごとに 1 ページ |
| Conditions（前提条件） | Orbit & stations（軌道と地上局）、Analysis cases（解析ケース）、Phases（フェーズ） |
| Project（プロジェクト） | Diagnostics（診断）、Settings（設定）、Units & definitions（単位と定義）、Sources（出典） |

`fune gui` を実行すると、Overview ページが表示され、タイトルの下に部品、モード、ネット、ケースの数が出るはずです。

- 検索: 検索ボックスをクリックするか、`Ctrl+K`（Mac では `⌘K`）を押します。数文字を入力して、ページ、部品、ネット、モードを選ぶと、そこへ移動します。
- サイドバー: `Ctrl+B`（`⌘B`）で、サイドバーを開閉します。閉じると、アイコンの細いレールが残ります。
- 診断のカウンター（ブランチ名の下のエラーと警告）: `fune check` と同じ件数です。クリックすると、Diagnostics ページが開きます。
- Change history（変更履歴）: この行は、このセッション（ページを読み込んでから）に行った変更を、新しい順に並べたポップオーバーを開きます。各項目には同じ編集をするコマンドと、それをコピーするボタンがあります。取り消しとやり直しの操作も並びます。ポップオーバーの見出しには **Undo**（元に戻す）と **Redo**（やり直す）のボタンがあり、`Ctrl+Z`、`Ctrl+Y` と同じ操作をします（[取り消しとやり直し](#取り消しとやり直し)）。
- Language（言語）: 「Language」の行で、日本語と英語を切り替えます。選択はブラウザーに記憶されます。
- Appearance（外観）: 「Appearance」の行で、「Follow the OS」（OS に従う）、「Light」（ライト）、「Dark」（ダーク）を選びます。

GUI がサーバーに接続できないと、カウンターの下に赤い「Cannot reach the server」（サーバーに接続できません）の枠が出ます。`fune gui` がまだ動いているかを確かめてください。

## 多くのページで使うパターン

### 編集ダイアログと「同じ操作のコマンド」のプレビュー

複数の値が必要な編集では、ダイアログが開きます。部品の追加、モードの追加、要求の追加、名前の変更などです。ダイアログはウィンドウの上寄りに置かれます。ウィンドウより高いときはダイアログの中でスクロールし、ボタンには届いたままです。`Enter` で確定します。確定のボタンと同じく、ダイアログにエラーがない間だけ有効です。入力が有効になるまで、確定のボタンは無効のままです。

確定する前に、ダイアログには **Same operation as a command**（同じ操作のコマンド）という箱が出ます。次の内容が入っています。

- 同じ編集をする `fune` コマンド（複数のこともあります）と、**Copy command**（コマンドをコピー）ボタン。
- 「Files changed:」（変わるファイル:）の行。開くと、ファイルごとの差分を読めます。ラベルは new、modified、deleted、renamed です。
- 警告と、編集が拒否される場合はその理由。

プレビューはドライランから作られるので、確定のボタンを押すまで、何も書き込まれません。CLI を学ぶときや、コマンドをスクリプトにコピーするときに使ってください。既存のレコードのフィールドが抜け落ちる編集のとき（たとえばケースを置き換えるとき）は、プレビューに「Removed from <file>: <keys> (not in the new record)」と出ます。

小さな編集ではダイアログを使いません。ホバーしたときに鉛筆が出る値は、クリックして入力し、`Enter` で保存、`Escape` で取りやめます。値は単位つきのテキストで入力します（たとえば `1.2 kg`）。サービスは`fune set` とまったく同じ読み方をします（[値の書式](cli.md#値の書式)）。エラーは欄の下に表示され、何も書き込まれません。

編集が保存されると、変わったファイルを示す短いメッセージが出ます。その間に設計がほかで変わっていると（ファイルの編集や CLI の実行）、メッセージに「The design changed elsewhere」と出ます。GUI は最新の設計を読み込み直すので、もう一度操作してください。

### 使われているものの削除

ケース、フェーズ、モード、形態、回線、地上局、カタログの項目は、そのページから削除できます。まだ何かが参照していると、削除は拒否されます。ダイアログのプレビューが、何が参照しているかを挙げたメッセージで、理由を示します。たとえば「Analysis case hot_imaging cannot be removed: referred to by `default_case` in analysis/common.toml; `quantify.cases` of requirement(s) R_STORAGE. Change those first」のようになります。先にそれらを変えてから、削除してください。CLI も同じメッセージを出します（[ケース](cli.md#ケースフェーズ形態)）。削除が通った場合は、取り消せます。

### 不足している入力の行と対処の操作

解析の入力が不足していると、サブシステムのページの **Missing inputs (n)**（足りない入力）の下に、その一覧が出ます。各行は不足している項目と理由を示します。埋め方が分かる行には、リンクのような操作があります。

| 操作 | 開くもの |
|---|---|
| "Enter value"（値を入れる） | 値を入力するダイアログ。部品がカタログの項目を使っているときは、書き込み先を選びます。「Override on this part」（この部品の上書き）か、カタログの項目（それを使うすべての部品に適用）です |
| "Set on a part"（部品に値を入れる） | 部品を選んで値を入力します。その部品の上書きとして保存されます |
| "Assign an existing part"（既存の部品を割り当てる） | ある役割を担う部品を選びます。その部品の種類が、その役割を持つ種類に変わります |
| "Add a part"（部品を追加） | 不足している種類に合わせて設定済みの、Add component ダイアログ |
| "Pick a part"、"Pick a catalog item"、"Pick a link"、"Pick a configuration"、"Pick a maneuver" | 設計の中にある選択肢の一覧 |
| "Add a mode"、"Add a maneuver"、"Add a ground station"、"Add a comm link"、"Add an analysis case" | そのページの追加ボタンと同じダイアログ |

これらは`fune analyze` がコマンドとして表示するものと同じ対処です（[チュートリアルのステップ 11](first-satellite.md#11-解析を実行して不足している入力を埋める)）。どのダイアログにも、コマンドのプレビューが出ます。不足している入力はOverview のバジェットと、Requirements ページ（「Inputs are missing」）にも出ます。

### ケースの選択

どのサブシステムのページにも、右上に「Analysis case」（解析ケース）というラベルの選択欄があります。最初の項目は「Automatic (default where needed)」（自動。必要な解析だけ既定）です。ケースが必要な解析は既定のケースを使い、ほかの解析はすべてのモードを見ます。既定のケースが決め手になるときは、「Default for analyses requiring a condition: <case>」と表示されます。ケースを選ぶと、そのページのすべての解析を、そのケースで実行します。横の **Recompute**（再計算）ボタンは、解析をもう一度実行します。

選択はページのアドレス（`?case=<ID>`）に保存されるので、リンクを共有できます。リンクが指すケースがもうなければ（削除した、名前を変えた、作成を取り消した）、ページは既定の選択を表示し、「Analysis case <ID> no longer exists; showing the default selection.」という通知を出します。

### 形態の選択

Layout ページには「Placement configuration」（配置の形態）という選択欄があり、最初の項目は「Base」（基準）です。どの形態の部品の姿勢を見て編集するかを選びます（[概念](concepts.md#形態)）。形態を選んで部品を動かすと、姿勢はその形態だけに書かれます。「Manage configurations」（形態を管理）で、形態を追加、編集、名前変更、削除します。選択はアドレス（`?configuration=<ID>`）に保存されます。

### 取り消しとやり直し

`Ctrl+Z`（`⌘Z`）は直前の編集を取り消し、`Ctrl+Y`（`⇧⌘Z`）はやり直します。どちらもウィンドウのどこでも使えますが、文字を入力する欄の中では入力の取り消しになります。サイドバーの「Change history」ポップオーバーの見出しにある **Undo** と **Redo** のボタンや、System diagram ページのツールバーのボタンも使えます。

履歴は `fune undo` と `fune redo` が使うものと同じです。そのため、CLI の編集を GUI から取り消すことも、その逆もできます。ポップオーバーの一覧はこのブラウザーのタブで行ったことを表示します。ページを読み込み直すと空になりますが、取り消しの履歴そのものはプロジェクト（`.fune/history.json`）に残っています。編集のあとにファイルがほかの方法で変わっていると、取り消しは拒否されます。

### 表とツリー

表の見出しは並べ替えができます。1 回クリックすると昇順、もう一度で降順、3 回目で元の順序です。ツリーには「Expand all」（すべて開く）と「Collapse all」（すべて閉じる）があります。検索ボックスは見えるものを絞り込みますが、設計は変えません。

### 3D ビュー

Layout ページと、Thermal ページの「Thermal image」タブは、衛星を 3D で表示します。

| 操作 | 方法 |
|---|---|
| 回転（軌道を回る） | 左ボタンのドラッグか、指 1 本のドラッグ。どの軸まわりにも回せ、上下を逆にもできます |
| 平行移動 | マウス: 中ボタンか右ボタンのドラッグ、または Shift を押しながら左ドラッグ。トラックパッド: 2 本指のスクロール |
| ズーム | マウスのホイール、またはトラックパッドのピンチ。ポインターを中心にズームします。右上の縮小と拡大のボタンは、中心を基準にズームします |
| ある方向から見る | 右下の**ビューキューブ**の面、辺、角をクリックします。傾きのない、いちばん近い正立の視点へ動きます。角を選ぶと、立方体の対角線に沿った Y 字形の眺めになります |
| ビューを回す | ビューキューブの横にある 2 つの曲がった矢印（反時計回りと時計回り）が、見ている方向を軸に画面を回します。角から見ているときは 120°、それ以外は 90° です |
| リセット | 右上の **Home**（家の形）ボタンで、カメラと向きを初期状態に戻します |
| ヘルプ | 右上の疑問符のボタンが、これらの操作を一覧にします |

### 2D の図のビュー

System diagram ページは同じ考え方を 2D で使います。ホイールかピンチでズームし、2 本指のスクロールか、背景または中ボタンのドラッグで平行移動します。`+`、`-`、`0`（全体を表示）、`1`（100 %）、`F`（選択した項目へズーム）のキーは、文字入力の欄にフォーカスがないときに使えます。

## Overview

表示するもの: Overview ページはプロジェクトのダッシュボードです。サブタイトルに、名前と、部品、モード、ネット、ケースの数が出ます。

- KPI カード: 解析から得た代表的な数値で、たとえば「Mass margin」（質量余裕）です。各カードには値、充足率のバー、判定の色、関連する数値の行があります。カードをクリックすると、その元になっているサブシステムのページが開きます。設計にとって表示するものがないカードは、表示されません。
- Conditions: 軌道と環境のカードの 2 行目です。
- バジェットのパネル: バジェットの種類（質量、電力、データ）ごとに 1 つです。パネルにはバジェットの題、モードまたはケース、余裕、限度とシステム余裕、サブシステムごとの行（「Current」、「With growth」、配分、余裕）、合計があります。質量バジェットでは設計に推進系があると、「Dry」（乾燥）と「Wet」（推薬込み）の合計と推薬の行が出ます。「Limit from requirement R_… (edit it there)」は、限度の置き場所を示します。値のない部品の行は集計していないものとして挙げられます。バジェットの不足している入力も挙げられます。
- Diagnostics: エラー、警告、情報の件数と「See all」（すべて見る）。

編集できるもの: このページでは何も編集しません。カードと行は編集できるページへのリンクです。

典型的な作業: 編集のあと、ここに戻って、バジェットが赤くなっていないかを確かめます。

## Design

### Components

表示するもの: Components は部品を一覧にします。タブは 3 つです。

- Overview: サブシステム、グループ、組立品ごとにまとめたカード。
- Tree（ツリー）: `parts/` のディレクトリ構造を持つ、プロダクトツリー。
- Table（表）: 部品ごとに 1 行。ID、系、種類、カタログの項目、数量、質量、状態ごとの電力、未設定の属性、診断を並べます。並べ替えができます。

「Search parts」（部品を検索。ID、種類、カタログの項目）と系のフィルターで、一覧を絞り込めます。部品を選ぶと詳細が開き、サブシステムをまたいで、その部品のすべてが表示されます。

| セクション | 表示するものと、編集できるもの |
|---|---|
| Basics（基本） | 種類、カタログの項目、「Trade candidates」（トレード候補）の中で選んだ候補、数量、冗長度、成熟度、系、場所 |
| 属性の表 | サブシステムごとに 1 つの表（Mass、姿勢系、Power、Thermal など）。各値と出どころ（カタログ、上書き、出典）、上書きを消してカタログの値に戻すリセットボタンを表示します。値をクリックすると編集できます。**Add parameter**（パラメーター追加）は、出典、出典内の場所、注記つきで属性を追加します |
| Placement（配置） | 「Mounted on」（取付先）、「Mounting part」（取付先の部品）、「Mount point」（取付点）、オフセットと向き（X、Y、Z まわりの角度）、導出した機体座標系の姿勢、形態ごとの姿勢の上書き |
| Connections（接続） | ポートと、それぞれが接続するネット |
| State per mode（モードでの状態） | 各モードでの部品の状態と、モード表へのリンク |
| Harnesses（ハーネス） | 部品に接続するケーブルのセグメント |

編集できるもの: 値（クリックして編集）、配置、部品そのものです。**Add** はコンポーネント追加のダイアログを開きます。系か組立品を選び、「From catalog」（カタログから。カタログを検索して項目を選ぶ）か「Kind only」（種類だけ）を選んで、ID を付けます。部品のメニューには「Rename」（名前を変える）、「Group…」（グループにまとめる）、「Delete」（削除）があります。名前を変えると、参照がすべて一度に書き換わります。

典型的な作業: カタログから部品を追加し、質量の上書きを設定します。Add を押し、項目を選び、ID を付けて確定します。次に部品を開き、質量の値をクリックします。

### Catalog

表示するもの: Catalog はすべてのカタログの項目を一覧にします。自分のカタログ（`local/…`）と共有カタログです。タブは「Tree」と「Table」です。フィルターはカタログ、種類、検索ボックスです。「Group by」（分け方）はツリーをカタログ、製造元、種類、成熟度、タグ、サブシステムで分けます。項目を選ぶと、「Basics」（名前、英語名、製造元、型番、成熟度、タグ、データシート）、「Values」、「Ports」、「States」と、一覧「Used by」（その項目を使っている部品）が表示されます。

編集できるもの: 値と、項目の名前の変更と削除です（部品が使っている間は、削除が拒否されます）。「Add to design」（部品として設計に追加）は、項目から部品を作ります。**New catalog item**（カタログ品を作る）は、項目を作ります。既存の部品の値をコピーすることもできます。共有カタログの項目は読み取り専用です。「To change a value, open a PR on the shared repository or override it on the part.」と表示されます。**Shared catalogs**（共有カタログ）ボタンは、共有カタログの一覧と状態を表示するダイアログを開きます。

- **Fetch**（取得）は`catalog.lock` に記録されたコミットをダウンロードします。`fune catalog fetch` と同じです。
- **Update**（更新）は記録を最新のコミットへ進め、追加、削除、変更された項目を表示します。
- **Add shared catalog**（共有カタログを足す）は、名前、git の URL、リビジョンを尋ねます。`fune.toml` にエントリを追加します。そのあと Fetch を押してください。

取得や更新のあとは、`catalog.lock` をコミットしてください。カタログのダイアログは一度に 1 つだけ表示されます。

典型的な作業: 新しいコンポーネントを一度だけ記述します。New catalog item を押し、出典つきで値を入力してから、「Add to design」を使います。

### Layout

表示するもの: Layout は配置の 3D エディターです。見出しに、配置済みの部品の数と、未配置の部品の数が出ます。市松模様の球は重心の印です。

- Parts tree（部品のツリー、左）: プロダクトツリーです。目のボタンで部品を表示・非表示にでき、「Show only <part>」で 1 つだけを取り出せます。
- シーン: 箱をクリックして選びます。「Operation」（操作）はシーンの中の「Move」（移動）か「Rotate」（回転）のハンドルを選びます。「Snap」（スナップ）は動きを丸め、「Structure opacity」（構造の不透明度）は構造を透明にして、中を見られるようにします。
- Helpers（補助表示）: 「FoV」（視野の円錐）、「Origin axes」（原点の軸）、「Grid」（格子）、「View cube」（ビューキューブ）、「Sun」（太陽）、「Wireframe」（枠線だけ）の切り替えです。
- 軸、法線、ボアサイト: 色つきの線で、スピン軸、磁気トルカの軸、法線、ボアサイト、推力の方向を示します。
- Findings（所見）: 「Show analysis findings as colours」（解析の所見を色で示す）は、構造の解析が見つけた重なりと、プルームや視野の干渉に色を付けます。一覧「Findings」はそれを挙げ、部品を選べます。大きさのない部品はひし形のマーカーで描かれます。
- Placement configuration（配置の形態、上部）: 上の形態の選択を参照してください。ビューの操作は[3D ビュー](#3d-ビュー)にあります。

編集できるもの: 「Placement of <ID>」のパネルで、取付先、位置、向きを数値で変えられます。移動や回転のハンドルで、部品をドラッグすることもできます。形態を選んでいるときは、変更はその形態に入ります。

典型的な作業: 新しい部品を配置します。Components で追加し、Layout で箱を選んで、「Mounted on」、取付点、オフセットを設定します。

### System diagram

表示するもの: System diagram は部品をカード、ネットを線として描きます。電源と信号の接続で、電源系はレールごとに色分けされます（バッテリー、太陽電池アレイ、非安定化バス、安定化レール）。部品のグループはコンテナとして描かれます。

- ツールバー: 「Visible subsystems」（表示する系）は、サブシステムを隠します（構造は既定で隠れています）。「Layers」（層）は「Power」、「Signal」、「GND」の表示を切り替えます。「Group identical」（同種をまとめる）は、同じカタログの項目と接続を持つ兄弟の部品を、1 枚のカード「×N」として表示します。
- Details（詳細）パネル: カードか線を選ぶと、詳細が出ます。ネットには「Rail voltage」（レール電圧）、「Current limit」（電流制限）、「Protocol」（プロトコル）、ポートの一覧と、「Disconnect」（切り離す）、「Delete」があります。
- ズームのボタンとキー、全体のマップ、**Undo** と **Redo** のボタン。

編集できるもの: 位置、経路、接続です。カードやグループをドラッグすると動きます。ポートから別のポートへドラッグすると、接続します。どちらもネットにないときは、ダイアログがネットを作ります。線の端をドラッグすると、カードの縁の別の場所へつなぎ直せます。線の区間をドラッグすると、手で経路を決められます。区間をダブルクリックすると曲がり角が増え、曲がり角をダブルクリックすると消えます。「Reset positions」（位置を自動に戻す）は、動かしたカードを自動配置に戻し、手で描いた配線は残します。「Reset positions and wires」（位置と線を自動に戻す）は、両方を消します。

典型的な作業: 新しい部品を電源のレールにつなぎます。部品の電源ポートから、レールのポートへドラッグします。

### Modes

表示するもの: Modes はモード表です。列がモード、行が部品です。マトリクスのタイトル行は「Component × mode」（部品 × モード）です。「Lighting period」（表示する期間）で「Sunlit」（日照）と「Eclipse」（蝕）を切り替えると、蝕のときの状態の上書きが見えます。マトリクスの下には1 台あたりの消費電力、成長余裕込みの合計電力、「Available」（利用可能）な電力、「Margin (after system reserve)」（システムの予備を引いたあとの余裕）が出ます。パネルはエネルギーバランスが繰り返す、名前つきのモードシーケンスを一覧にします。「Use for analyses」（解析に使う）で 1 つ選びます。

次の操作で編集できます。

- 状態の切り替え: セルをクリックすると、部品のオンとオフを切り替えます。右クリックするか `D` を押すと、別の状態とデューティ（各軌道周回のうち、別の状態で過ごす時間の割合。0 から 1）を選べます。凡例は「● On」、「◐ Duty」、「— Off」です。
- モードの列: 「Add mode」（モード追加）は、モードを作ります（別のモードをコピーできます）。列のメニューで、名前の変更、削除、左右への移動ができます。モードには「Maximum duration」（最長継続時間）と、最長継続時間の評価に使う「Timing」を設定できます。
- 保存: セルの変更は下書きとして集められます。下のバーに「Save the mode table (n cells)」と出て、ダイアログと同じコマンドのプレビューを示します。合計と余裕には下書きがすでに反映されています（「not saved yet」）。保存を押すと書き込み、破棄もできます。

典型的な作業: ダウンリンク中はカメラをスタンバイにします。DOWNLINK の列でそのセルを右クリックし、状態を選んで、保存します。

### Requirements

表示するもの: Requirements には 2 つのタブがあります。

- Compliance（適合表）: 要求ごとに 1 行です。要求の文、制約、ケース、「Verified by」（確かめる先。解析かバジェット）、結果、判定を並べます。上部には件数として、「Requirements」、「Met」（満たす）、「Warning」（注意）、「Violated」（違反）、「Not verified」（未確認）が出ます。未確認の行は理由を示します。「No analysis check or budget is linked」、「Inputs are missing」、「The analysis failed」などです。
- Requirements: 要求の一覧です。「Add requirement」（要求を追加）、「Edit」（編集）、「Remove」（削除）があります。

編集できるもの: 要求です。ダイアログでは短い名前、記述（と英語の記述）、制約する量の次元、出典、制約の向きと値、それが成り立つべきケース、そして確認する解析とそのチェックのキー、または確認するバジェットを指定します。入力した量は`fune requirement add` とまったく同じ読み方をします。

典型的な作業: 質量の限度を追加します。Add requirement を押し、量は Mass、向きは「at most」（以下）、値を入れ、確認するバジェットは「mass」にします。Overview の質量バジェットに、その限度が表示されます。

## Subsystems

表示するもの: サブシステムごとに 1 ページあります。Power、Communication、Thermal、姿勢系、C&DH、Propulsion、Structure、Payload です（Payload にはまだ解析がありません）。名前は、プロジェクトの語彙に従います。サブシステムのページには右上にケースの選択と **Recompute** ボタンがあり、その下にタブが並びます。タブはサブシステムによって異なります。

| タブ | 対象 | 表示するもの |
|---|---|---|
| Overview（概要） | すべて | 「Analyses」（解析）の表。解析ごとに 1 行で、種類、主な結果、判定、不足している入力の数を示します。行をクリックすると、その解析のすべての KPI、グラフ、判定の文、不足している入力が開きます。Thermal ページの Overview は、代わりに、節点の温度と範囲のグラフを表示します（保管、動作、性能の各帯域、定常状態の点、過渡の棒） |
| Maneuvers（マヌーバ） | Propulsion | 実行順のマヌーバ。Add、Edit、Remove があります。下を参照してください |
| Thermal image（熱画像） | Thermal | 部品を、その節点の温度で色分けした 3D 表示です。温度の出どころ（全ケースで最悪、定常ケース、選んだ時刻の過渡）、再生、カラースケールを選べます。軌道の図は、太陽の側を示します |
| Couplings and surfaces（結合と表面） | Thermal | 節点間の伝導と放射の結合、外面のコーティング、コーティングの表。値を入力すると、上書きが書かれます。節点の温度への影響は、保存の前に表示されます |
| Analysis results（解析結果） | Thermal | 解析ごとに 1 枚のカードで、判定、値、表を表示します（ほかのサブシステムでは、これらを Overview に表示します） |
| Modes（モード） | Power、C&DH、Thermal、姿勢系 | サブシステムのモードごとの値を、日照と蝕に分けて表示します（GUI のモードビュー。`fune mode view <system>`）。Power は、「Where sunlit power goes」（日照中の電力の行き先）と、バッテリーから出す蝕の電力も表示します。姿勢系は、各モードの姿勢則と機器を表示します |
| Time series（時系列） | すべて | 時系列解析のグラフ。そのような解析を実行すると表示されます |
| Settings（設定） | すべて | サブシステムの設定と、それがあるファイル。値はその場で編集できます。表の下には、解析ごとに折りたたみのブロックがあり、その解析に渡した入力を表示します |

各解析は[解析のページ](../analyses/index.md)で説明しています。

編集できるもの: 設定をその場で編集でき、不足している入力の対処もできます（上を参照）。2 つのページにはさらに操作があります。

- Communication ページには「Add a link」（回線を足す）ボタンと、一覧「Comm links」（通信の回線）があります。回線を追加するときは、方向、送受信機の部品、地上局が性能を持っている帯域を指定します。一覧の各回線には編集と削除のボタンがあります。編集では回線の名前を変えることもでき、その場合は、その回線を指すダウンリンクの選択と要求のチェックも書き換わります。要求のチェックがその回線を指している間は、削除が拒否されます。損失と変調方式はSettings タブで書きます。
- Structure ページには「Geometry findings」（幾何の所見）が並びます。箱どうしの重なりと、円錐の中にある部品です。所見には理由をつけて「Acknowledge」（承知する）操作ができます。承知した所見は警告ではなくなりますが、一覧に残ります。「Withdraw」（取り消す）で、承知を取り下げられます。

典型的な作業: Power ページで、エネルギーバランスの不足している入力を、行の操作で埋めて、行に判定が出るまで進めます。[チュートリアル](first-satellite.md#11-解析を実行して不足している入力を埋める)では、同じことを CLI で行っています。

### Maneuvers

Maneuvers タブは各マヌーバを、区分、方式、スラスタ、目標つきで一覧にします。**Add a maneuver**（マヌーバを追加）は、`fune maneuver add` と同じフィールドを持つダイアログを開きます。マヌーバには順序があります。1 つを削除すると、次のマヌーバが、その前のマヌーバにつなぎ直されます。

## Conditions

### Orbit & stations

表示するもの: `conditions/` の設定（軌道、地上局、期間）を表にしたものと、それに依存する解析です。

- Beta angle and eclipse seasons（β と蝕の季節変動）: 1 年にわたるグラフです。
- Altitude history（高度の推移）: 抗力による軌道の減衰です。太陽活動のプリセットと、宇宙天気の表を取得してあれば、日付つきの値を使えます。表がないときは、Settings で取得するようにページが案内します。
- Visibility per ground station（地上局ごとの可視）。

次の操作で編集できます。

- 「Create this case」（このケースを作る）は、蝕が最長の日付か、β が最小の日付を、解析ケースにします（ケースの ID と、任意でモードを尋ねます）。
- **Add ground station**（地上局を足す）は、ID、単位つきの緯度と経度、任意で高度と最小仰角を尋ねます。-90 から 90 deg の外の緯度や、0 から 90 deg の外の最小仰角は拒否されます。地上局は名前の変更も削除もできます。通信の解析が一覧に挙げている間は、削除が拒否されます。帯域ごとの性能は設定に書きます。
- 軌道の値は設定の表でその場で編集します。

典型的な作業: 回線設計で使う地上局を追加し、可視を確かめます。

### Analysis cases

表示するもの: Analysis cases は`cases/` のケースを、名前、説明、モード、フェーズ、開始時刻、ファイルつきで一覧にします。各行にある 2 つのアイコンのボタンが、ケースの名前の変更と削除をします（ツールチップは「Rename case <ID>」と「Remove case <ID>」）。メニューのボタン「Open with this case」（このケースで開く）は、サブシステムのページの一覧を表示します。1 つ選ぶと、そのケースを設定した状態でページが開きます。

次の操作で編集できます。

- Add a case（ケースを足す）: ID、表示名、説明、モード、フェーズ、不確かさの側、熱環境、β 角（単位つき。たとえば `60 deg`）、周回数、太陽距離、開始時刻を指定します。すでにある ID でケースを追加すると、置き換わります。プレビューは削除されるフィールドを挙げます。
- Choose phase（フェーズを選ぶ）と Enter start time（開始時刻を入力する）は、ケースのフィールドを 1 つ編集します。
- Cases from the worst days（最悪の日からケースを作る）は、フェーズの軌道のミッションの幾何から、3 つのケースを作ります。
- 名前の変更は、既定のケースと、要求に書かれたケースを書き換えます。削除は何かがそのケースを参照している間は拒否され、メッセージが何が参照しているかを示します。

典型的な作業: 最悪の蝕のケースを追加し、「Open with this case」で、そのケースの Power ページを見ます。

### Phases

表示するもの: Phases は`phases/` を順に一覧にします。名前、順序、「Starts when」（始まりの条件）、「Ends when」（終わりの条件）、継続時間、使うモード、上書き、そのフェーズを指すケースを示します。

編集できるもの: **Add phase**（フェーズを追加）、**Edit**、**Remove** はほかのページと同じように使えます。ケースがフェーズを指している間は、削除が拒否されます。**Edit overrides**（上書きを編集）は、軌道の上書き（設計の軌道をコピーして、値を 1 つずつ編集）と、モードごとの姿勢則の上書きのためのダイアログを開きます。上書きはそのフェーズを指すケースにだけ適用されます。

典型的な作業: 廃棄フェーズの軌道を低くします。Edit overrides を押し、設計の軌道をコピーして、高度を変え、ケースでそのフェーズを指定します。

## Project

### Diagnostics

表示するもの: 設計のすべての診断を、重さ、コード、メッセージ、ファイルつきで表示します。「Filter by severity」（重さで絞る）のフィルターもあります。`fune check` と同じ結果です。

編集できるもの: ここでは何も編集しません。エラーはそれが指すもののページか、ファイルで直します。

典型的な作業: サイドバーのカウンターが赤くなったら開き、エラーから順に片付けます。

### Settings

表示するもの: Settings には 3 つの部分があります。

- Project（プロジェクト）: 「Name」（名前）、「Location」（置き場所）、「Branch」（ブランチ）、「Revision」（版）、「Schema version」（スキーマの版）。
- External data（外部データ）: 任意のデータセット（DE440 の天体暦、宇宙天気の表、放射線データ）です。各行に、データセットの ID、状態（「Installed」読み込み済み、「Cached」キャッシュ済み、「Missing」未取得）、サイズ、取得した日時、それを使うもの、ライセンスまたは出典の表示が出ます。
- Settings の表: 「Conditions」、「Analysis」、「Budget」に分けた表で、列は Key（キー）、Value（値）、File（ファイル）です。

編集できるもの: 設定の表の値はその場で編集します。「Not set」（指定しない）のキーには入力した値を指定できます。データセットの **Fetch**（取得）ボタンは、`fune data fetch <ID>` と同じく、そのデータセットをダウンロードします（[インストール](install.md#任意のデータセット)）。`gh` や `curl` がないなどのエラーは、行の下に表示されます。

典型的な作業: 日付つきの値で軌道寿命の解析を実行する前に、宇宙天気の表を取得します。

### Units & definitions

表示するもの: 3 つのタブがあります。**Units**（単位）はすべての単位を次元と SI 係数つきで表示し、「Try a unit」（単位の試し打ち）は、入力した単位を解釈して、次元と SI の値を表示します。**Attributes**（属性定義）は組み込みと自分の属性定義、**Kinds**（種別定義）は、種類の定義です。

編集できるもの: 「Add attribute」（属性を追加）と「Add kind」（種別を追加）で自分の定義を作れ、名前も変えられます。組み込みの定義は名前の変更も削除もできません。

典型的な作業: 入力したい単位、たとえば `mN*m*s` が使えるか、その次元は何かを確かめます。

### Sources

表示するもの: 登録簿 `sources/` です。ID、種類、名前、参照、リビジョン、取得日、SHA-256、配布の扱い、日付、作成者を示します。「Open」（開く）は参照を開きます。

編集できるもの: **Add source**（出典を追加）と **Edit** は、出典を書きます。共有カタログの出典は読み取り専用です（「Shared」）。出典を削除するには `fune source rm` を使います。値がその出典を引いている間は、拒否されます。

典型的な作業: データシートの値を入力する前に、データシートを登録します。そうすると、各値がそれを引用できます。

## 典型的な作業と実行する場所

| 作業 | 場所 | 対応する CLI |
|---|---|---|
| 設計が健全かを見る | Overview、Diagnostics | `fune status`、`fune check` |
| カタログから部品を追加する | Components、Add | `fune part add <ID> --catalog <ITEM>` |
| 値を変える | Components、部品、値をクリック | `fune set <PART>.<ATTR> "<value>"` |
| 部品をモードに入れる | Modes、セルをクリック | `fune mode set <MODE> <PART> <STATE>` |
| 部品を配置する | Layout、または Components の Placement | `fune part place <ID> --on <PART> …` |
| 2 つのポートをつなぐ | System diagram、ドラッグ | `fune net connect <PART>.<PORT> <NET>` |
| バジェットを読む | Overview | `fune budget mass\|power\|data` |
| ケースを指定して解析を実行する | サブシステムのページ、ケースの選択 | `fune analyze <ID> --case <CASE>` |
| 不足している入力を埋める | サブシステムのページ、行の操作 | `fune set …`（ダイアログに表示） |
| 要求を追加する | Requirements | `fune requirement add …` |
| 通信リンクを追加・編集する | Communication、Comm links | `fune link add …`、`fune set analysis.comm.link.<name>.<field> …` |
| 間違いを取り消す | `Ctrl+Z`、または Change history | `fune undo` |
| 外部データを取得する | Settings、External data | `fune data fetch <ID>` |
| 共有カタログを追加する | Catalog、Shared catalogs | `fune catalog source add …` と `fune catalog fetch` |

GUI はすぐにファイルへ保存し、隠れた状態を持ちません。変更を残すには、git でコミットします。
