# 概念設計に向けたロードマップ

2026-11-06。小型衛星の過去の概念設計書（47 件）と計算シートのテンプレートを調べ、概念設計で繰り返し必要になるのにまだ存在しないものを、優先順に並べました。
各項目は GitHub Issue #1〜#15（親は #16）で管理しています。P1 の項目は閉じていて、#14（P2）、#15（P3）、#16（親）、#17（高次の重力場）が開いています。
件数は「47 件の設計書のうち、その項目を扱っていたもの」です。
今ある解析は [analyses/index.md](analyses/index.md) に一覧があり、お使いのバージョンのものは `fune analyze ls` で見られます。

## 調査で分かったこと

- テーマの約半分は深宇宙、惑星、ラグランジュ点、約 10% は月、約 30% は地球周回です。地球中心の軌道だけでは過半数をカバーできません。
- 設計の実体は、学年を越えて受け継がれる計算シートのテンプレート（部品選定、モードごとの電力、SAP/BAT、リンク、外乱、構造、熱、表面特性）です。
  同じ部品の値がタブごとに食い違う、清書用のタブへ値を手で転記するといった問題があり、単一の情報源、モード表、レポートの表の自動生成が直接の対策になります。
- 設計書の形式は、LaTeX が 30 件、Typst が 6 件、Word が 5 件、Google ドキュメントが 2 件でした。2025 年は 4 チームのうち 3 チームが Typst を使いました。
- 口頭試問で繰り返し指摘された点（食中の電力解析がない、マージンを含むかが不明、有効数字、表の番号、姿勢要求の種類の区別）は、
  モデルの整合性検査とレポートのテンプレートで機械的に防げます。

## 文書生成の方針

第 1 段階はこの方針に従っています。「未実装」と書いた部分は、あとの段階です。

- Typst を主な経路にします。設計書を書く人に使われ始めていて、Rust の `typst` クレートで iwafune に組み込めます。`fune report export` は `exports/report/data.json` と `figs/*.svg`、Typst モジュールを書き出し、人は本文を `.typ` に書いて、生成した表を差し込みます（[report.md](report.md)）。
  - 未実装: `fune report build <ID>`（同じプロセスで Typst により PDF をビルドする）。
  - モジュールは `#mass-table()`、`#mode-power-table()`、`#link-budget()`、`#thermal-result()` などを提供します。
  - 書き出しは有効数字、単位、マージンを含むかどうか、表のレイアウトをそろえます。古い表が残らないよう、モデルのリビジョンを表の脚注に示します。
- ほかの形式には断片を書き出します（LaTeX の booktabs、CSV、docx の表、PNG/SVG）。未実装です。GUI のすべての表に「Typst / LaTeX / CSV / 画像としてコピー」を付けます（CLI と同じ機能）。
- 文書の定義はモデルに置きます（`reports/<ID>.toml`: 文書番号、バージョン、改訂履歴、入れる表と図、テンプレート）。未実装です。概念設計書、PDR、サブシステム設計書にはプリセットを用意します。
- 図面（CAD）は対象外です。iwafune からは BOM、面ごとの機器、重心と慣性を CSV で渡し、将来は STEP / glTF を書き出します。

## 予定しているアプリの機能（まだ Issue にしていないもの）

- 主な GUI の編集と解析のエンドツーエンドテスト（Playwright）を作り、CI に加えます。
- ファイルの監視と GUI への通知（外部のエディタや CLI で行った編集に、GUI がすぐ追従するようにします）。
- ベースブランチとの差分を示すページ（値とバジェットの変化）を作ります。
- トレードの候補（`candidates`）を並べて比べるビューを作ります。
- 外部の解析ツールとの受け渡し全般（入力と結果の形式、再実行の方法）を整えます。
- 分離後の初期運用を時間で追うシミュレーション（電源投入、展開、デタンブリング、太陽捕捉）を作ります。
